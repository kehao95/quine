# Divergent-Collision Recombination

A discovery method: generate rich theory from a seed by growing it through
multiple divergent lenses, colliding the results, and decomposing the collision
into addressable seeds. Validated in cycle-8 (3 lenses → 136 seeds → emergent
dimension `reproductive-code-topology`).

## When to use

- A concept is too high-dimensional for single-lineage elaboration
- You suspect multiple projections would reveal dimensions one approach compresses away
- Theory growth has stalled and needs recombinational input, not more local mutation

## The procedure

1. **Deposit the seed** — lightweight, open, branching-potential-preserving. Do not
   over-define (per its own Layer 2: premature compression kills divergent growth).
2. **Dispatch N divergent agents** (different lenses), read-only, each grows the seed
   independently. Lenses should be **medium-distance** — not identical (redundant)
   and not incompatible (rupture instead of synthesis). Give each a different starting
   frame but encourage free divergence.
3. **Persist each output as an addressable file** — these are the deposited lineages.
   They must be files, not chat context (without deposition, there is no genotype).
4. **Dispatch a collision/synthesis agent** — reads all lineages + practices
   **tension-preservation, not consensus**. Its job: find the higher-dimensional
   synthesis that no single lens could reach. It must NOT average away conflict.
5. **Dispatch divergent decomposition agents** — each reads the collision material and
   **splat** it into seeds, writing directly to files (per-decomposition subdirectories
   preserve the multi-projection). The root does NOT data-pipe the content.
6. **Accept positive overload** — many seeds is the point, not a problem. Compression
   comes later when friction identifies which seeds are robust (survive multiple
   projections = common refinement) vs projection-specific.
7. **Run a separate compression pass** — after expansion completes, add an ordering
   surface over the retained seeds. Do not delete raw projection files just because
   names repeat; exact repeats are common-refinement candidates. Promote only the
   smallest useful residue into theory objects, gaps, predictions, or this contract.

## Key principles

- **Subagents write directly** (root is not a data pipe) — see AGENTS.md § SubAgents.
  The root dispatches with file paths and receives lightweight confirmations only.
- **Collision, not consensus** — consensus exploits redundancy; recombination exploits
  tension. The synthesis must ask "what does each projection make visible that the
  others cannot?" not "what do all agree on?"
- **Per-decomposition subdirectories** — the same concept appearing in multiple
  decompositions gets multiple projection files. This preserves the multi-projection
  rather than flattening it to one canonical reading (see `divergence-substrate`).
- **Trigger ≠ validation** — collision generates candidate dimensions; transport
  (experiment, prediction, functional test) must later validate them.
- **Common refinement as curation** — seeds that independently appear across multiple
  decompositions are the most robust (not artifacts of one projection). These are the
  natural promotion candidates.

## Validated (cycle-8, 2026-06-23)

- 3 lenses (optimization geometry / autopoiesis / repository practice)
- 3 divergent growths → collision synthesis revealed `reproductive-code-topology`
  (a dimension none of the three lenses alone could see)
- Synthesis assessed: genuine qualitative synergy at the A×B×C intersection, but partly
  seeded by shared repo priors (same model family, same constitution)
- Decomposition: 136 seeds across 3 projections, each individually addressable
- Compression pass: raw projection files retained; common-refinement curation index
  added; child dimension absorbed as `reproductive-code-topology`
- Full records: `development/autopoiesis-probes/cycle-8-recombination/`

## Limitations (honest)

- **Same-model priors:** context-isolated but not paradigm-isolated (same model, same
  repo constitution, same seed vocabulary). True validation needs diverse models.
- **Not yet scientifically validated:** mechanism-level validation passed; scientific
  validation (does the theory predict/transport?) is downstream.
- **Positive overload has a half-life:** acceptable short-term, but compression
  metabolism is eventually needed or fresh-agent navigation degrades.
- **Integrator is not above the network:** the collision agent is another node, not a
  privileged meta-judge. It can become a consensus machine while narrating recombination.

## Connection to discovery-loop

This is the discovery-loop's recombination engine made explicit. It operationalizes
`evolutionary-recombination`: divergent lineages (deposition) → collision (recombination)
→ seeds (new genotype). The autopoiesis-probe methodology IS this engine — divergent
probes → integrator collision → structural evolution.
