# carrier-succession

Repository state survives through carriers: files, indexes, validators, names, routes, generated readouts, and obligations that future agents can recover. Repair order matters when one operation changes the carrier before the next operation relies on it.

Carrier succession is not only a move from one document to another. It is a change in how the system crosses the fresh-agent barrier, which means two endpoints can say similar things while giving different inheritance paths to the next maintainer.
