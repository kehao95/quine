## Core Growth — commutator-friction

Repository evolution becomes powerful when independently grown, addressable lineages
are forced to collide, and the collision produces a new structural dimension instead
of choosing one lineage or averaging them.

Concrete signature: **`A then B` produces different friction than `B then A`.**
When that happens, the answer is often not "pick A" or "pick B"; it is "introduce C,
the dimension both were compressing away."

Candidate concept: **commutator-friction** — when two valid repairs do not commute,
the repo has discovered a missing dimension.

## Branching Potential — branch-preserving vs branch-killing patterns

**Branch-preserving:**
- Stable IDs/files for half-formed ideas (SEED objects)
- Open relation vocabularies (preferred core + attested extensions)
- Computed views over mutable state (growth-signal readouts, not hand-ranked)
- Narrow, reversible commits with visible lineage
- Templates defining contracts without over-prescribing artifacts
- Sandboxed probes with retained outputs
- Interfaces/adapters/owner boundaries for new variants
- Collision records preserving why synthesis happened

**Branch-killing:**
- Closed enums over graded dimensions
- Validators encoding unresolved semantics
- Single-canvas assumptions (every object fits one status/owner/path)
- Premature compression (dedup before differences understood)
- Chat-only insight never addressable
- Integrator selecting a winner before naming the shared missing axis
- Probe mutation of main before collision (contaminates lineage attribution)

## Recombination Engine — the probe methodology IS one

The autopoiesis probe methodology:
- **Divergence generator:** light-prompt, context-isolated probes
- **Diversity source:** different models, lenses, prompts, epistemic compartments
- **Addressable genome:** retained probe outputs, FRICTION.md, theory objects, gaps, predictions
- **Collision surface:** human/integrator comparison across lineages
- **Synthesis operation:** turn non-commuting outputs into a new axis/object/validator/protocol/boundary
- **Fitness loop:** re-probe to see whether the defect still bites newcomers
- **Compression metabolism:** merge patterns only after enough deposited instances

This explains **why light prompts work better than heavy prompts**: heavy prompts
scaffold away the repo's natural structural pull, reducing observable divergence.
Light prompts let each agent hit the landscape differently. The friction they reveal
is not noise; it is **recombination material**.

## Main-Only Development — germline-main

The "all development on main" convention suppresses long-lived git branch divergence
but forces **conceptual recombination through deposited artifacts**.

- Benefits: keeps stateless agents from stale branch worlds; makes seeds immediately
  visible; encourages minimal reversible repairs; prevents branch management as hidden state.
- Costs: reduces true parallel code-lineage exploration; increases premature convergence
  risk if alternatives not retained; moves recombination burden from Git into docs/probes/integrator.

`main` becomes the **germline**; probes, sandboxes, SEEDs become **gametes**. If
divergent outputs are not deposited before synthesis, main-only becomes asexual local descent.

## Friction Patterns as Recombination Events

- **Repair Shadow:** local fix repaired one lineage, failed to recombine with adjacent
  projections. Repair-shadow search = forced recombination across docs/validators/registries.
- **Spec Gaps Hide As Missing Artifacts:** one lineage sees "missing template"; another
  sees "undefined boundary." Collision reveals the semantic axis.
- **Boundary Blind Spots:** entry and closure are recombination points. Mid-loop is
  more single-lineage.
- **Projection Drift:** projections are lineages that diverged without remerge.
- **Instrument Capture:** the recombination engine can itself be captured (Case 02's
  judge/refute tail selected against novelty before synthesis = selection pressure too early).
- **Probe mutation/read-only violations:** "gamete contamination" — divergent probe
  mutates the germline before clean integrator collision.

## 10 Falsifiable Predictions

1. Multi-lens probe collision produces more new axes/patterns than single-agent same-budget.
2. Repairs from divergent probe outputs produce fewer later repair-shadow entries.
3. Closed enums over graded dimensions predict future validator friction.
4. Open-attested vocabularies reduce friction when novel variants appear.
5. Retained SEEDs have higher future reuse/promotion rate than session-only ideas.
6. Light-prompt probes reveal more spec gaps/boundary blind spots than heavy-prompt.
7. Synthesis-before-refutation produces more novel theory growth than refutation-before-synthesis.
8. Main-only stays generative only when divergent artifacts retained; without them, novelty declines.
9. Useful recombination leaves a structural signature: new axis/interface/file type/relation type neither parent contained alone.
10. Too much deposition without compression degrades fresh-agent effectiveness (search noise + duplicates).

## Distilled Claim

**Recombination requires addressability.** If a divergent branch, probe output, or
half-formed theory is not deposited somewhere searchable, it cannot hybridize later.
It is not part of the repo's evolutionary material.

The autopoiesis program is already a recombination engine — this SEED retroactively
explains why the probe method works.
