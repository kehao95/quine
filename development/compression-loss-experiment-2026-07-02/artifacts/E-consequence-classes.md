# Scheme E — Consequence-Based Clustering of discovered-sparks

Method: each spark reduced to licensed predictions/prohibitions/actions, stripped of topic vocabulary, then grouped where the *actual test* overlaps, not the domain words. Result: 18 merged classes (56 sparks) + 13 singletons + 0 class-zero. Filenames omit `.md`; all live in `Paper/incubator/discovered-sparks/`.

**Members:** diversity-pressure-discriminator-novelty-search-control-arm, drift-vs-selection-confound-in-single-descendant-lineage-chains, elicited-vs-heritable-variation-wedge
**Synthesis:** All three reject reading one run's pattern as proof of selected heritable change and prescribe the same fix: a control that reproduces the same surface pattern without real heritability, then check if the effect survives it.

## Self-reported losses

This scheme discarded nearly all domain narrative: theory-spine chains, links metadata, and the specific repo objects (dorm-06, succ-31, self-immunity-P1) each spark leans on became bare member lists a future agent must re-open to use. Several merges are boundary judgment calls — C1 vs. C2 (both "add a control arm" for different failure modes), C16 vs. C17 (both reject a borrowed external comparison, one methodological, one quantitative) — another reader could split or fuse differently. Cross-class links (S4's heritability sub-claim relates to C4; S10 relates to C4's salience member) went unrecorded except here. Extraction was delegated to four sub-agents on disjoint batches; I did not re-verify each of the 69 extractions against source text, so any misreading propagates uncaught into its class.
