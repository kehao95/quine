# active-inference

The repository is a **dynamic environment to be sensed**, not a static
configuration to be read.

- Verify state before **irreversible or high-stakes** action; for reversible
  generative work, act and let friction correct — defaulting to up-front
  verification locks the agent into a defensive posture that squeezes generative
  action
- Apply the [descriptive-vs-normative](./descriptive-vs-normative.md)
  distinction when deciding whether the implementation, account, or expectation
  needs revision
- All cached state is potentially drifted
- General methods (search, discovery) beat hard-coded knowledge

Hard-coded facts rot. Discovery mechanisms adapt.

**Two kinds of unknowns** should not be confused:

- **Discoverable facts** belong to repository or system truth. Search the current
  state, control plane, evidence, and implementation before declaring them unknown.
- **Preferences and tradeoffs** belong to explicit project direction or the
  system's own normative commitments. Decide early when they materially shape the
  work, and record the chosen default when one is applied.
- Treating discoverable facts as open questions creates unnecessary uncertainty.
  Treating normative commitments as if they were discoverable facts creates false
  certainty.

**Epistemic humility:** The system's knowledge has boundaries. Some questions
have no definite answer; some situations exceed the agent's competence. When
genuinely uncertain:

- Uncertainty is stated explicitly, not masked by confident-sounding guesses
- "I don't know" is a valid and sometimes optimal response
- When stakes are high and confidence is low, prefer reversible steps and route
  to procedure-reflection
- Action under uncertainty is bounded—reversible steps preferred, irreversible
  steps flagged
