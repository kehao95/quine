# Working in Quine

Do not alter repository history — no force push, no rewriting or deleting commits unless requested by the user.
Everything else is recoverable via git and is the agent's to enact.

[README](./README.md) introduces Quine through several overlapping descriptions.
This file supplies working guidance for participants.

## Start From the Work

- Ideas, philosophy, and research: [philosophy](./Paper/philosophy/README.md),
  [theory](./Paper/theory/README.md), and [discovery procedures](./Paper/procedure/README.md).
- Implementation or control-plane changes: [DEVELOPMENT.md](./DEVELOPMENT.md).
- Existing work and blockers: [status](./development/status/README.md).
- Finish a substantive interval: [CLOSURE.md](./CLOSURE.md).

Follow the current task and read the relevant material. When a distinction
matters, make it explicit; [ontology](./Paper/philosophy/ontology.md) offers
working vocabulary. Preserve evidence and leave useful work where another
participant can find and continue it.

Descriptions, procedures, and these instructions can be revised as the work
changes. Act on your own judgment within the user's instructions.
