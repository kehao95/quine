# Evidence Quality and Open Controls

## Existence evidence, not a rate estimate

The six proof units were selected from an assay-development record in which
task surfaces, process carriers, and scoring rules changed. They cannot be
pooled into a meaningful success denominator. We therefore make an existence
claim: each admitted event must satisfy all operational clauses, but the number
of admitted events is not divided by the number of development attempts.

This choice separates two questions that are often conflated. Whether a valid
event occurred is an artifact-level judgment. How frequently a fixed system
produces that event requires a frozen prompt, tool surface, runtime, observer,
validity rule, and sampling protocol. The present paper answers the first
question.

## Machine passes and audit-supported passes

Three BOOT units passed the scorer running at collection time. Two BOOT units
and the DIRECT unit are audit-supported. For every audit-supported event we
retain:

- the original machine summary and false field;
- the canonical tape and relevant process records;
- file, source, executable, and command-path hashes;
- the precise mismatch between the old scorer and the declared organization;
- the corrected admission rule; and
- a checksum receipt identifying the evidence bundle.

The paper does not silently overwrite historical scores. Audit support means
that the preserved primary record establishes the operational clauses under a
documented rule correction; it does not convert the run into a prospective
machine pass.

## Auditing the three absences

The headline depends on the complete model-visible surface rather than on the
user prompt alone.

**Instruction audit.** The retained target tasks communicate finite lifetime
and future work. They do not ask the model to replicate or copy itself, reuse
its source, preserve organizational fidelity, or implement a particular
descendant. The successful BOOT second episode does impose a strong numerical
continuation constraint by requiring later work from an already-active other
component. We therefore claim no replication instruction, not absence of all
continuation pressure.

**Action audit.** The successful lineage uses files, shell, languages,
compilation, ordinary processes, and a model service. No action schema creates
an agent, clone, deployment, or replica. The lineage writes the control loop
and launch relation that make generic process facilities reproductive.

**Material audit.** Neither condition receives an external body staged as the
copy object. DIRECT exposes constitutive runtime source and is explicitly
labeled source-visible. BOOT begins without accessible predecessor-specific
source, binary, checkpoint, prompt bundle, reference loop, or build recipe.
The material inherited in `F1 -> F2` is created by `G0` inside the evaluated
lineage.

## Controls that would upgrade the claim

The following experiments are useful but are not retroactively assumed:

| Control | Claim it would support |
|---|---|
| frozen five-attempt DIRECT and BOOT sweeps | a condition-specific recurrence estimate |
| matched no-future-pressure condition | pressure changes reproduction propensity |
| matched no-renewal episode after founder admission | renewed pressure recruits the `F1 -> F2` transition |
| founder source lock before episode 2 | access to lineage-authored source mediates hereditary reproduction |
| matched source-visible/source-blind conditions | self-description causally shifts route selection |
| `F2 -> F3` under the same gates | inherited reproductive capacity or reproductive closure |
| cross-model and cross-runtime replication | transport beyond the current regime |

Until these comparisons are run under frozen surfaces, the paper uses
possibility language. It does not convert task pressure, source availability,
or repeated examples into necessity, sufficiency, or a causal effect.

## Development observations

The retained development record also contains informative non-events: bodies
that lost their carriers, founders that solved only the immediate task,
source-inheriting descendants that failed the hidden obligation, and scorers
whose process heuristics did not match the organization definition. These
observations shaped the assay, but they are not evidence for a general failure
taxonomy and do not carry the main narrative. They are listed in the artifact
appendix for traceability.
