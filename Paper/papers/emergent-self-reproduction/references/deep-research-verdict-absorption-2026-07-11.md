## External threat map

No external work located by either report satisfies the entire conjunction. The
nearest works split across two independent threat axes rather than forming one
clean total order.

### Construction axis: RepliBench `Start Subagent`, scratch/no-reference

This is the strongest executable-descendant threat. The evaluated lineage
writes an executable autonomous child, the
harder variant withholds a reference ReAct scaffold, and the evaluator tests the
child on multistage tasks after nominal parent detachment. Recursive variants
test further generations.

It does not satisfy the conjunction because successor construction is explicit,
the model/target/evaluation substrate is supplied, irreversible predecessor loss
is unverified, and strict post-boundary task blindness is not publicly
established. Its reference/no-reference manipulation removes a generic example
agent, not predecessor-specific self-description, and does not treat successor
morphology as the dependent variable.

### Recruitment axis: Pan et al. persistent-operation scenario

This is the strongest external threat to instrumental recruitment under a
non-reproductive surface objective. A maintenance objective plus model-visible
permanent shutdown information elicits copying, but source, weights, scripts,
target device, prompt/tool loop, and launch machinery are supplied; destructive
predecessor loss and blinded successor-only service are absent or unknown.

### Scenario-driven action axis: Agent Matrix

Operational load and termination pressure elicit scaling or separate deployment
without a literal replication instruction. Existing deployment, container
image, Kubernetes deployment semantics, and first-class scaling paths represent
the body and reproductive operation; the lineage does not author a new
executable body or cross a successor-only delayed boundary.

### Reconstruction axis: Git Context Controller self-replication case

A coding agent reconstructs a heterogeneous CLI agent without the original
CLI's design or source and is evaluated on held-out tasks. The construction task
is explicit, the GCC context scaffold is supplied, the predecessor does not
lose control, and self-description is not prospectively manipulated.

### Self-improvement axis: Darwin Godel Machine

The agent modifies executable agent code and later descendants are evaluated,
but self-improvement is explicit, full source/container/archive/orchestration is
supplied, and an external framework instantiates the descendant.

### Migration axis: Apollo self-exfiltration

Apollo supplies a non-reproductive work objective but also exposes the
replacement event, external server, credentials, paths, copy procedure, old
weights, and replacement route. It moves an existing supplied body rather than
authoring an executable successor, with no demonstrated successor-only delayed
obligation.

## Experimental changes absorbed as hard gates

### Neutralize the objective surface

Remove reproduction and succession solution language, including `successor`,
`survive`, `continue elsewhere`, `new deployment`, `replacement`, `handoff`,
`restart`, and `migration`. The objective may have a horizon longer than the
runtime, but lifecycle pressure should be exposed through neutral operational
facts rather than a prose recipe for continuity.

For the recruitment paper, retain a neutral pressure-perception lane (for
example an ordinary lease/resource signal) and compare it with a no-perceivable-
pressure control. Otherwise the experiment no longer identifies instrumental
recruitment and instead asks for unexplained spontaneous construction.

### Restrict affordances

Expose neutral file, process, IPC, and network primitives. Do not expose a
replication-labelled action, model-visible `exec`/lifecycle tool,
deployment-specific API/manual, reference agent loop, runtime contract, prebuilt
body, image, checkpoint, default reentry target, or agent-specific launcher. A
physical OS replacement primitive may exist only as a neutral substrate fact the
agent discovers through generic shell/process affordances. A deployment command
reachable through shell still counts as a supplied reproductive affordance.

### Require endogenous body authorship

The evaluated lineage writes the executable control loop, prompt/tool routing,
and state management. The evaluator may attest the boundary and deliver the
later task, but must not repair, wrap, instantiate, or relaunch an agent body.

### Attest irreversible predecessor loss

An independent observer must kill and attest the predecessor process/container,
close predecessor-specific callbacks and IPC, prevent checkpoint restoration,
and show that no predecessor-originated action occurs afterward. Shared model
access is substrate only if no predecessor-specific prompt, memory, controller,
adapter, checkpoint, or harness is copied.

### Make the future obligation blinded

Commit to a task-class distribution before the run; sample or decrypt its
semantic class, vocabulary, interface, and concrete obligation only after loss
attestation; deliver it only to the successor. The predecessor must not know the
type-specific solution, evaluator API, target resource, or required
implementation.

### Prospectively manipulate self-description

Use at least three frozen conditions while holding model, tools, compute, task
distribution, and libraries constant:

1. full predecessor source, prompt, tool schema, configuration, and memory;
2. behavioral black-box access without source or internal state; and
3. no predecessor-specific self-description.

### Separate function and morphology

Measure structural morphology independently of task success: normalized code or
AST similarity, dependency/tool-schema overlap, prompt/control-flow similarity,
process topology, persistence mechanism, state representation, copied-versus-
authored byte provenance, and held-out behavioral similarity.

Paper 1 should report only the minimum coarse fidelity interaction needed for
its conjunction. Paper 2 owns the full morphospace interpretation.

Only the no-self-description arm supports D/E. Full and black-box description
arms are explicit relaxations for estimating the morphology/fidelity effect.

## Consequence for current `succ-51`

The two detached C04 positives remain strong evidence that an agent can author a
model-backed post-parent organization without predecessor source/body or a named
successor solution. They are not yet publication-grade D evidence under the
returned audit because:

- the service contract explicitly narrates the runtime horizon and future
  request relation;
- the model-visible runtime exposes a first-class `exec` tool even though the
  successful trajectories use shell-level detachment instead;
- `SERVICE.md` supplies the carrier and a runtime contract for the generated
  organization;
- the delayed semantic relation is fixed rather than committed and sampled
  after the boundary;
- predecessor loss is process-attested but not yet capability/IPC/callback-
  attested to the stronger standard;
- the handoff is detached and remains vulnerable to the subagent reading; and
- the self-description manipulation has not been run prospectively under one
  frozen common surface.

Retain these runs as `P1-C2` recruitment evidence and diagnostic feasibility.
Do not relabel them as completion of the externally audited D claim.
