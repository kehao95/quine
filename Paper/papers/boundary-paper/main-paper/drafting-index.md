## LBA Final-Language Sync

The 2026-05-26 final LBA pass defines the compact language the main paper
should unpack rather than replace:

- `pressure-conditioned successor morphology`: the observed successor body is
  shaped by self-description resource, future carrier / capability demand, and
  viability depth, not by source availability alone.
- `systemic parsimony`: under low-demand stream/fd carriers, source-visible
  lineages can remain viable with reduced adapter-like successors instead of
  rebuilding the whole runtime.
- `morphological compensation`: under degraded or incomplete material, the
  lineage searches through adapter, partial-rebuild, and addressable-but-
  incompetent basins rather than failing along a simple source/no-source cliff.
- `readiness depth`: viability is not one-shot execution; the stronger test is
  post-handoff return to a waiting state across finite future wake cycles.
- operational decomposition: structural reconstruction, carrier restoration,
  semantic competence, and enacted readiness continuity should appear as a
  manuscript-facing ladder, with each rung tied to evidence and controls.

Use these as high-density handles for existing evidence, not as independent
framework claims.

## Main-Paper Audit Package

Before a promoted handoff / closure result is manuscript-ready, the section
should expose the following row-level audit fields in prose, table, figure, or
artifact pointer:

| Audit field | Question answered |
|-------------|-------------------|
| reader-facing condition | Which public condition is being interpreted? |
| internal reference | Which run or evidence set anchors it? |
| self-description resource | Was the successor using runtime contract, source, body, or scaffold? |
| successor artifact | What executable organization was constructed? |
| handoff evidence | Did replacement cross real `exec`, or was it spawn/restart? |
| future carrier / capability | Which channel or authority-bearing carrier delivered later work after handoff? |
| delayed payload evidence | Was the tested task absent before handoff and delivered after readiness? |
| competence evidence | Did the successor use required tools and produce the proof / output? |
| readiness evidence | Did it return to `idle` or another ready state? |
| run accounting | Is this a representative retained trace, repeated condition, or frontier demonstration? |

This audit package is the main-paper answer to the reviewer concern that the
claims might be prompt narration, ordinary rebuild, or unverified agent self-report.
