# Structural Elicitation in a Frozen POSIX Agent: Environmental Affordance Fields for Artificial Agency

**Abstract.**
Place a frozen, instruction-tuned language model in a Unix workspace as a long-running process and
give it a shell and one standing prime — *"you are a running process; there is no task; inspect,
then act freely."* It does not idle: it explores, and then it acts — and **what** it does is
directed by the **static structure of its environment**, with no task and no reward. Removing the
explicit instruction reveals **functional, environment-directed action without an explicit task**.

We test this with **matched-pair** experiments scored only on **un-fakeable filesystem and exec
events** (the agent's narration is never credited): a *structure* arm and an otherwise-identical
*control* differing in one structural feature. Across a repertoire — a broken file is **repaired**,
a missing sequence element **created**, a dangling reference's **target written**, a cross-surface
version conflict **reconciled**, an opaque executable **run** — the structure arm fires in **96/102**
runs and the control never does (**0/85**) across **three independent model families** (gpt-5.4,
deepseek-v4, glm-5.2).

The pull is not merely a coding-prior artifact for the discrepancy mode. Ported to non-code prose —
a handbook referencing a file that does not exist — the same discrepancy creates the named target
above matched controls on gpt and glm. A substrate probe shows the behavior realized at the POSIX
layer: under a read-only mount the agent still issues a real write *attempt* the kernel refuses.

This is a phenomenon of the **missionless / underspecified regime**: specific tasking **gates** the
structural pull in the tested conflict cell, while weak underspecified prompting leaves it intact. So
we report a minimal, environment-coupled dynamic — absent a concrete goal or a reward, a frozen
policy's functional behavior is supplied by the **structure of its environment**, read through a
latent prior. We contribute the phenomenon, a matched-pair method on an **un-fakeable POSIX
substrate**, and its cross-model robustness. The underlying **mechanism** — why structure latches
behavior, and what gates it — is future work.
