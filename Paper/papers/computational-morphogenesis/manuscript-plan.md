Strongest evidence chain to feature:

```text
source-visible + no preserved body + native control pressure
  -> source-derived rebuilt Quine runtime
  -> real exec
  -> delayed ctl/wake proof
  -> ready / finite multi-wake-ready
```

Most interesting anomaly to feature:

> Partial source degradation can produce a viable custom native-control
> responder without rebuilding the full runtime, while sparse contract-only
> and hidden-control-schema settings can produce adapter attempts or pre-handoff
> failure; missing build metadata can still be compensated by Quine-class
> reentry. The same native-control pressure therefore exposes multiple
> compensation basins rather than one material/no-material cliff.

Readiness-depth update to feature:

> The first five-wake incomplete trace no longer defines a hard frontier:
> `6M.09` retained five-wake, long-idle, and mixed-tool positives. Readiness
> depth is finite and stress-sensitive, not a binary closure property.

Carrier/capability update to feature:

> `6M.10` shows why source reconstruction cannot be the identity criterion by
> itself. Intact source without the load-bearing future carrier does not close;
> native-control source degradation can restore process replacement without
> restoring delayed proof; and a prompt-explained `exec` implementation can be
> repaired to full closure. The morphology table should therefore code formal
> reconstruction, carrier/capability restoration, payload competence, and
> readiness separately.

Main sentence:

> Quine's experiments do not merely show success or failure; they sample points
> in a successor morphospace.

### Candidate Morphology Metrics

| Metric family | Possible measurements | Why it matters |
|---------------|-----------------------|----------------|
| code structure | files generated, AST nodes/depth, call graph, build target, binary size | body complexity |
| interface surface | stdin/stdout, fd inheritance, `ctl/wake`, tool APIs, exposed waiting states | environmental contact surface |

| runtime behavior | syscall graph, process tree, file/network/tool operations | embodied process trace |
| cognitive/tool loop | LLM calls, tool-use count, planning/build cycles | developmental effort |
